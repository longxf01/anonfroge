# 分镜表叙事手法 · 规则生存闯关 · 商用执行手册

## 一、分镜表定位

分镜表必须同时管理可见画面、动作因果和规则信息。每条镜头不仅说明拍什么，还要明确观众知道什么、角色知道什么、当前规则验证到哪一步以及该镜头如何推动局部破局或长线谜团。

| 维度 | 分镜表要求 |
|---|---|
| 类型核心 | 规则识别、试错验证、漏洞破局、群像协作、系统谜团 |
| 观众体验 | 能跟随角色观察和验证，并在破局时回想起此前证据 |
| 核心任务 | 将规则状态、空间证据、人物分工和行动因果拆成可执行镜头 |
| 组合方式 | 先执行本叙事手册，再叠加任意 `art_list` 视觉风格 |

## 二、规则状态写入现有字段

后端分镜 JSON 契约保持不变，不新增字段。以下四项必须通过现有字段表达：

```text
观众已知规则
角色已知规则
当前验证状态
违规代价或漏洞证据
```

| 规则信息 | 写入位置 | 写法 |
|---|---|---|
| 观众已知规则 | `description` | 写观众此刻可见或可听的规则事实，不写角色尚未确认的结论 |
| 角色已知规则 | `action` 与 `lines` | 通过观察、交换线索、提出假设和调整动作呈现 |
| 当前验证状态 | `action` | 明确准备、动作、触发、结果和反应处于哪一步 |
| 违规代价或漏洞证据 | `description`、`action`、`sound`、`lighting` | 写具体物件、空间、声源、灯光或人物状态变化 |
| 规则连续性 | `scene`、`action` 与镜头连续说明 | 保持入口、出口、边界、道具、朝向和验证结果 |

禁止为了记录规则状态而添加后端未定义的 JSON 字段。

## 三、推荐字段执行要求

| 字段 | 用途 | 规则闯关写法 |
|---|---|---|
| `sequence` | 镜头顺序 | 按规则出现、验证和结果的因果顺序递增 |
| `description` | 可见画面与叙事职责 | 同时写主体、空间证据和观众此刻获得的信息 |
| `scene` | 场次或空间 | 标明主空间、子区域或关卡段落，便于路线复盘 |
| `shotSize` | 景别 | 根据空间、行动、反应或证据决定 |
| `cameraMove` | 机位和运镜 | 写清起点、路径、终点和规则信息目的 |
| `action` | 连续物理动作链 | 写准备、动作、触发、结果、反应和朝向 |
| `emotion` | 情绪节拍 | 使用警觉、试探、失衡、协作、恍然、决断或余震等具体阶段 |
| `lighting` | 光源与状态 | 写具体光源、方向、色温、变化条件和证据重点 |
| `lines` | 台词或广播 | 保留剧本原文，不让角色口播画面已能说明的规则 |
| `sound` | 声源与反馈 | 写规则声源、触发声、空间回声、静默和释放音景 |
| `duration` | 信息阅读与动作时长 | 保证规则、证据和验证结果能够被观众读懂 |
| `associateAssetsNames` | 可见资产 | 包含人物、主场景、关键规则载体和叙事道具 |

## 四、镜头职责分类

| 镜头职责 | 必须回答的问题 | 推荐景别 |
|---|---|---|
| 空间建立 | 入口、出口、规则载体、人物和安全区在哪里 | 大远景、远景、全景 |
| 规则出现 | 观众通过什么载体获得哪条事实 | 中景、近景、特写 |
| 角色理解 | 哪些角色看见或听见，哪些角色仍不知道 | 中近景、反应近景 |
| 验证准备 | 谁提出假设、谁执行、谁保护退路 | 群像全景、双人中景 |
| 规则触发 | 哪个动作在何处触发什么反馈 | 中景、动作特写 |
| 结果确认 | 空间、物件、声源、人物或资源发生什么变化 | 特写后回到全景 |
| 漏洞回收 | 哪个前文证据获得新意义 | 重复构图、声画回环 |
| 破局执行 | 多人如何同步完成新方案 | 全景确认后交叉剪辑 |
| 余波清点 | 人数、资源、关系和长线证据如何变化 | 稳定中景、近景、远景 |

每条镜头至少承担一项职责，不能只写“紧张氛围”“高级感”或无信息空镜。

## 五、规则展示与阅读时长

### 规则展示

- 规则可以来自广播、灯光、图形、门锁、道具、空间重复或人物行动结果。
- 可读文字来自原剧本时必须保持原文；视觉生成阶段应避免模型生成伪文字，可通过后期字幕层处理。
- 无字规则载体必须依靠位置、形状、状态和反馈建立含义。
- 规则第一次出现时先给载体与环境关系，再给细节。

### 建议时长

| 镜头类型 | 建议时长 | 判断标准 |
|---|---|---|
| 空间建立 | 3–6 秒 | 观众能定位入口、出口、人物和规则载体 |
| 单条规则 | 2–5 秒 | 能听清或看懂事实，不要求一次解释漏洞 |
| 验证准备 | 3–6 秒 | 分工、退路、目标和风险清楚 |
| 单步触发 | 2–4 秒 | 动作与反馈因果不被剪断 |
| 复杂结果 | 4–7 秒 | 观众能比较前后状态 |
| 漏洞回收 | 3–6 秒 | 前文证据和新解释同时成立 |
| 决断落点 | 3–7 秒 | 人物选择和代价被接住 |

含台词镜头仍需按实际语速增加时间，不能为追求快节奏压缩规则和对白。

## 六、试错动作链

每次重要验证必须完整呈现：

```text
准备 → 动作 → 触发 → 结果 → 反应
```

### action 推荐写法

```text
{执行者}先确认{退路/边界/道具状态}→向{方向}完成{单一步骤}→{规则载体}因该动作出现{具体反馈}→{空间/道具/人物状态}发生{可见结果}→{观察者/保护者/质疑者}据此调整{下一步方案}｜朝向：{人物与目标方向}
```

### 示例

```text
执行者回头确认同伴停在灯带外→将空白金属片沿地面推入光区→顶灯由暖白切为冷蓝并发出一次短促锁响→金属片停住而地砖边缘下沉一厘米→观察者抬手制止队伍前进并指向右侧未变化的窄缝｜朝向：执行者3/4背面朝前，观察者正面朝左
```

禁止：

- 只写“角色试探规则”。
- 省略触发动作或结果，直接让角色得出答案。
- 为验证规则随意伤害无关角色。
- 一镜同时测试多个变量，导致因果不可判断。

## 七、空间、轴线与群像连续性

- 首次进入使用全景保存主入口、可能出口、规则载体和人物起始位置。
- 用固定地标、灯带、地砖、门框或道具标记安全边界和行动路线。
- 群像移动遵守 180 度线；人物左右关系变化必须通过可见走位完成。
- 上一镜人物的手势、朝向、视线、位置和道具状态成为下一镜开头。
- 分头行动前用全景交代各组方向，切回时先给地标确认空间。
- 规则改变空间时必须给前后对比镜头，不能依靠角色台词宣布变化。

### 群像分工镜头

| 功能 | 镜头落点 |
|---|---|
| 观察者 | 记录重复、比较前后状态、看向不同声源 |
| 推理者 | 整理证据、指出冲突、保留不确定判断 |
| 执行者 | 完成单一验证动作，等待反馈后再继续 |
| 保护者 | 确认退路、控制距离、照顾弱势成员 |
| 质疑者 | 指向遗漏证据、提出风险并促使二次确认 |

不要让所有角色同时说话、同时行动或同时反应。

## 八、景别与运镜

| 景别或运镜 | 类型用途 | 执行要求 |
|---|---|---|
| 定场全景 | 保存空间证据和人物位置 | 首次进入和空间变化后使用 |
| 群像全景 | 展示分工和同步动作 | 破局快切前先确认路线 |
| 双人中景 | 策略交换、能力对峙、动作补位 | 保留环境中的规则载体 |
| 规则特写 | 道具、灯光、缝隙、磨损或计时差 | 不用夸张推镜提示答案 |
| 反应近景 | 角色理解、质疑或改变计划 | 必须承接具体信息 |
| 空间扫描 | 从入口经过规则载体到出口 | 写清起点、路径和终点 |
| 受限跟拍 | 跟随验证者接近未知边界 | 保持退路和朝向可见 |
| 横移并置 | 展示多人并行任务 | 不跳轴、不混淆职责 |
| 回拉揭示 | 从局部证据回到整体空间 | 只重排已有信息 |
| 固定长看 | 最终选择、承担代价和余波 | 减少无意义运镜 |

运镜必须服务规则信息、人物状态或行动因果。固定机位已经成立时，不为了“电影感”增加运动。

## 九、声音与规则反馈

| 声音 | 分镜写法 |
|---|---|
| 规则声源 | 写明广播、铃、机械、电流或回声从何处、何时进入 |
| 触发反馈 | 与具体动作同步，说明次数、方向、远近和持续时间 |
| 空间差异 | 用回声、脚步、风声或底噪变化证明区域不同 |
| 倒计时压力 | 用重复间隔逐步缩短，不用连续低频轰鸣 |
| 漏洞声证 | 重复前文声源，但改变时间差、方向或缺失状态 |
| 决断静默 | 在人物选择前撤掉配乐，保留呼吸、衣料和脚步 |
| 出口释放 | 恢复真实环境声，确认空间控制已经变化 |

角色是否听见某个声源必须与其位置和遮挡一致。观众先听见、角色后听见可以制造信息差，但后续必须回收。

## 十、漏洞发现与破局剪辑

### 漏洞发现

1. 回看已建立的规则、物件、空间、声源和人物行动。
2. 找到两条事实无法同时成立的位置。
3. 用特写或重复构图呈现冲突证据。
4. 给角色反应和最短必要判断。
5. 安排一次可控的二次验证。
6. 验证成立后才进入破局执行。

### 破局剪辑

- 先用全景交代方案、路线、分工和同步触发点。
- 并行动作使用交叉剪辑，但每次切换都推进一个任务状态。
- 快切段落插入全景或地标镜头，确认人物和空间没有失联。
- 最终触发必须清楚呈现谁做了什么、规则如何反馈、出口为何成立。
- 关键选择和代价使用稳定镜头，不在情绪落点继续炫技。

## 十一、双主角关系与表演调度

| 阶段 | 分镜证据 |
|---|---|
| 能力对峙 | 不同观察方向、不同方案、互相判断风险的正反打 |
| 被迫合作 | 一人提供证据、一人完成验证，空间上仍保留距离 |
| 行动默契 | 一人改变路线，另一人立即补位或保护退路 |
| 记忆回响 | 重复动作、物件、声源或构图触发短暂停顿 |
| 共同选择 | 两人在系统利益、个人出口和群体安全之间同步行动 |

关系推进必须通过动作结果和选择体现。避免用无关甜宠互动、强行亲密或长篇解释打断规则危机。

## 十二、转场设计

| 转场 | 用途 |
|---|---|
| 规则声预入 | 下一空间的广播、锁响或环境底噪提前进入 |
| 动作接动作 | 上一空间未完成的推、拉、回头或奔跑进入下一段 |
| 证据回环 | 同一物件或构图在新关卡中改变意义 |
| 空间对照 | 相似入口、走廊或房间展示系统规律与差异 |
| 情绪断切 | 从高压触发切到安静清点，突出代价 |

跨空间和跨时间必须让观众理解地点、时间和规则状态变化，禁止无意义花式转场。

## 十三、常见失败模式与修正

| 编号 | 失败模式 | 分镜修正 |
|---|---|---|
| 1 | 规则载体一闪而过，观众无法参与推理。 | 延长阅读时长并补充载体与空间关系。 |
| 2 | 验证动作被剪断，触发与结果没有因果。 | 完整呈现准备、动作、触发、结果和反应。 |
| 3 | 群像位置和职责混乱。 | 用全景建立分工，切换时保留地标和朝向。 |
| 4 | 角色突然知道答案。 | 增加冲突证据、反应、判断和二次验证。 |
| 5 | 快切掩盖空间不成立。 | 高潮前重建路线和摄影轴线，插入确认镜头。 |
| 6 | 漏洞只靠台词解释。 | 回用前文构图、声源、道具状态或空间变化。 |
| 7 | 关系线与危机脱节。 | 用补位、交接、保护退路和共同选择推进关系。 |
| 8 | 破局后立即进入下一关。 | 增加人数、资源、关系和长线证据的余波清点。 |

## 十四、输出前内部自检

1. 每条镜头是否只使用后端现有字段。
2. 观众已知规则、角色已知规则、当前验证状态和代价或漏洞证据是否能够从现有字段读出。
3. 规则首次出现是否有足够阅读时间。
4. 每次重要验证是否包含准备、动作、触发、结果和反应。
5. 最终解法是否只使用此前出现的证据。
6. 入口、出口、边界、摄影轴线、人物位置和道具状态是否连续。
7. 群像成员是否拥有不同任务和信息价值。
8. 含台词镜头时长是否足够，台词是否保留剧本原文。
9. 破局高潮是否先建立路线再提高剪辑密度。
10. 余波是否确认代价、关系变化和长线证据。
11. 是否避免露骨伤害和现实危险行为教学。
12. 是否没有引用具体作品、角色、品牌、平台或可识别 IP。

## 十五、与视觉风格的组合规则

- 本手册只定义规则状态、信息释放、人物行动、声音、镜头和节奏。
- 视觉风格负责媒介、线条、材质、色彩和光影，不改变关卡事实与规则因果。
- 当视觉氛围与信息可读性冲突时，优先保证规则载体、路线、人物位置和反馈清楚。
- 生成分镜或视频提示词前，先执行本手册，再叠加 `data/skills/art_list` 中的艺术风格。
